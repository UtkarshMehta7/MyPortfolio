# Terminal Utkarsh ✈

Personal portfolio of **Utkarsh Mehta**, B.Tech CSE (Cloud Computing) at Lovely Professional University, designed as an airport terminal:

- **Boarding pass**: who I am and what I'm looking for
- **Departures board**: projects as flights, with a split-flap animation and live links
- **Pilot's logbook**: experience, training and education
- **Licences & ratings**: cloud certifications with verification links
- **The fleet**: each skill group flies as a real airliner (A380, 777, A350, 787, 747-8, A321neo)
- **Air traffic control**: contact

A **Day / Night** switch in the top bar changes the whole site. The hero is a cockpit view of a takeoff roll down runway 27, drawn live in the browser.

Everything on the site is editable from a private admin area at `/admin`, from any device.

### Always online
The public site never depends on the backend being awake:

1. **Snapshot builds:** every Netlify build downloads the latest saved content from the API and bakes it into the static site (`frontend/scripts/fetch-content.mjs`). If the API can't be reached, the build keeps the last copy.
2. **Rebuild on save:** after each save in `/admin`, the API calls a Netlify build hook, so the static site is updated about a minute later.
3. **Live refresh:** visitors also get the newest content straight from the API whenever it's awake.
4. **Keep-awake ping:** a GitHub Action pings `/api/health` every 10 minutes so `/admin` stays fast. It doesn't touch the database.

### Images
All photos are stored in the repo (`frontend/public/assets/`), so the site never depends on outside image links. They are free-licence stock photos that need no attribution, edited so no airline or manufacturer names appear. A skill group can also use its own photo via **Photo URL** in `/admin`.

## Admin area (`/admin`)

- One admin account only. There is no sign-up.
- **Account** tab: change the login username and password at any time. You need the current password, and every other open session is signed out.
- Passwords are stored only as bcrypt hashes, never in plain text. Sessions last 12 hours.
- Five failed logins from one address lock login for 15 minutes.
- **Locked out?** On Render, set `ADMIN_RESET` to `true`, restart, log in with the initial login, then set it back to `false`.
- Edit every section: boarding pass, stats, projects, logbook, certifications, skills and contact. Add, reorder and delete items, then **Save**.
- **Import** tab:
  - **GitHub**: pull public repositories and add the ones you choose as projects.
  - **Credly**: pull public badges as certifications.
  - **LinkedIn**: upload your LinkedIn data export (Settings → Data privacy → *Get a copy of your data*). Positions, Education, Certifications, Projects and Skills are read from it. LinkedIn doesn't offer an API for this, so the export file is the supported route.

## Deploy

### 1. Neon (database)
1. Create a project at [neon.tech](https://neon.tech).
2. Copy the **pooled** connection string (`postgresql://…-pooler…/neondb?sslmode=require`).

The table is created and filled with the starting content automatically on first start.

### 2. Initial admin login
Pick an initial username and create a hash of the initial password:
```bash
pip install bcrypt
python scripts/hash_password.py
```
Copy the printed hash (starts with `$2b$`). These are used only to create the account the first time; after that, change them from `/admin` → **Account**.

### 3. Render (backend)
1. On [render.com](https://render.com): **New → Blueprint**, and pick this repository. Render reads `render.yaml`.
2. Fill in the environment variables it asks for:
   - `DATABASE_URL`: the Neon connection string
   - `ADMIN_USERNAME`: your initial username
   - `ADMIN_PASSWORD_HASH`: the hash from step 2
   - `ALLOWED_ORIGINS`: your Netlify URL, for example `https://utkarsh-mehta.netlify.app`
   - `NETLIFY_BUILD_HOOK`: added in step 4 below
   - `GITHUB_TOKEN` (optional): a GitHub token with no scopes, to raise the API limit
3. Deploy, then open `https://<your-service>.onrender.com/api/health`. It should show `{"status":"ok"}`.

`JWT_SECRET` is generated by Render automatically. The free plan sleeps when idle, so the first request can take about 40 seconds. The site shows its built-in content until the API answers.

### 4. Netlify (frontend)
1. On [netlify.com](https://netlify.com): **Add new site → Import from Git**, and pick this repository. Netlify reads `netlify.toml`.
2. In **Site configuration → Environment variables**, add `VITE_API_URL` = your Render URL.
3. Deploy, then add the Netlify URL to `ALLOWED_ORIGINS` on Render if you hadn't already.
4. In **Site configuration → Build & deploy → Build hooks**, create a hook (name it "admin save"). Copy its URL into Render as `NETLIFY_BUILD_HOOK`.

### 5. GitHub (keep-awake ping)
In this repository: **Settings → Secrets and variables → Actions → Variables → New repository variable**, name `RENDER_URL`, value your Render URL. The *Keep API awake* workflow then runs every 10 minutes.

Render's free plan includes 750 hours a month, enough to keep one service running around the clock. GitHub pauses scheduled workflows after 60 days without repository activity; any commit or a manual run turns it back on.

## Run locally

```bash
# backend (uses a local JSON file instead of Neon when DATABASE_URL is empty)
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export ADMIN_PASSWORD_HASH='<hash>' JWT_SECRET='dev-secret'
uvicorn app.main:app --reload --port 8000

# frontend
cd frontend
cp .env.example .env
npm install
npm run dev     # http://localhost:5173  (admin: /admin)
```
